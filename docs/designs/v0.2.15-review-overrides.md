# v0.2.15 Design: Review-page track overrides + safe rip reuse

Status: design only (no code). Author: architect subagent, 2026-10-02.
Scope: two validation-day gaps - (1) the Review page cannot override
recommended tracks, (2) rip-reuse verification can cross-match two
different discs of the same movie. Plus one small surfacing item for the
v0.2.14 subtitle-language caveat.

Constraints: Python 3.14, PySide6 6.11, pytest, no new dependencies,
implementable in one ~30-60 min Forge session.

## Gap 1 - Review-page track overrides

### 1.1 Problem

`_fill_review_page` / `_fill_tracks_table` (ui/main_window.py) render the
`tracks_table` as 4 read-only text columns (Title / Length / Recommended
audio / Recommended subtitles). Wrong recommendations are unfixable from
the UI, and the subtitle column can be blank when the scan reports no
subtitle streams (nothing to select means nothing shown - v0.2.14 made
the recommender more aggressive, but the user still cannot *choose*).

### 1.2 UI choice: per-row combo boxes in the table

**Picked: in-table QComboBox cell widgets.** Rejected: a detail card
below the table.

Rationale, briefly:

- The table is a *row-per-title* surface; the two editable choices are
  exactly two values per row. Combos keep the mental model
  "title -> its audio + its subtitle" in one line, with zero extra
  navigation.
- A detail card needs row selection state, a "which title am I
  editing?" label, and a sync path back to the table - three new
  failure modes for one piece of state. That is the *more* complex
  surface, not the simpler one.
- QTableWidget already uses cell widgets in this codebase
  (`deps_table.setCellWidget` for "Open" buttons), and the theme
  stylesheets style QComboBox globally, so this matches the existing
  design system (`card_frame`, `section`, `muted`, theme.py palettes)
  with no new visual language.
- Novice surface stays identical until the user clicks a combo: the
  default selection is the recommendation, the label reads the same as
  today's text cell.

### 1.3 Review-page changes (ui/main_window.py)

`_fill_tracks_table` becomes the builder of both the display and the
override state:

- Columns 2 and 3 become `setCellWidget(row, col, QComboBox)` (no
  `NoEditTriggers` tension - headers keep their meaning, text is now
  inside the combo).
- **Audio combo** is populated from `title.streams_of("audio")`,
  one item per stream, `userData = sid`:
  `English DTS-HD Master Audio 7.1 (8ch)` - lang_name, codec_long (or
  codec), channels; fall back to `?`/`Audio N` when fields are empty so
  rows are never blank. Commentary/descriptive entries get a suffix
  `(commentary)` via the existing `is_commentary`/`is_descriptive`
  helpers so a novice sees why they were skipped.
- **Subtitle combo** is populated from `title.streams_of("subtitle")`
  **plus a leading `None` entry** (`userData = None`,
  label `(no subtitles)`). Item labels include the classification the
  task requires: `English (SDH)`, `English (forced)`, `Spanish` -
  using `recommend._classify_sub`-equivalent logic. When the scan
  reports no subtitle streams, the combo contains only
  `(no subtitles)` instead of a blank cell.
- Default `currentIndex` = the recommended sid from
  `recommend_title(t)`; if the recommended sid is not in the list
  (shouldn't happen), default to index 0.
- Changing either combo writes into a new per-window dict and updates a
  short per-row summary tooltip; no other page reacts (override state
  is *read at Start time*, like the filename fields).

New state on MainWindow:

```python
self._stream_overrides: dict[int, dict[str, int | None]] = {}
# {tid: {"audio_sid": int | None, "subtitle_sid": int | None}}
# A tid entry exists only when the user changed something; a key set to
# None means "explicitly no subtitle" (subtitle) and is never produced
# for audio (an audio combo always has >=1 entry and no None entry).
```

`_fill_review_page` clears `_stream_overrides` alongside
`_title_overrides`. Rescanning the same disc therefore resets overrides
- correct, since sids belong to a specific scan.

The muted explainer under the "Recommended tracks" section header gains
one sentence: `Click a track to see every stream on the disc and pick a
different one, or choose (no subtitles).` - the discoverability budget
is one line, not a new card.

### 1.4 v0.2.14 caveat surfacing (small item)

The recommender's "English not confirmed by the disc scan; verify the
language before relying on it." reason (recommend.py, appended when the
scan cannot confirm English) is currently invisible in the table.

Surface it **in the subtitle cell, not a new table element**:

- The subtitle combo gets `setToolTip` with the full
  `subtitle_reasons` text (all lines, caveats included; Qt tooltips
  show on hover over the combo).
- Cell text prefix: when the caveat is present, prepend a marker to the
  combo's current text, `English (SDH) ⚠`, and set
  `foreground`/`color` to the theme's warning palette entry on the
  combo (theme.py already resolves named colors; reuse the palette key
  used for the deps-table "Missing" status, i.e. `"err"`-adjacent
  caution tone - in light of the existing `theme_color(..., "err")`
  usage in `_show_deps_if_needed`).
- One muted line appears *under* the table (inside `rec_card`, the
  existing muted-label pattern) **only while at least one row carries
  the unconfirmed-English caveat**: `⚠ One or more subtitle picks are
  not confirmed English by the disc scan - hover a row for details.`
  This is computed in `_fill_tracks_table` from
  `sel.subtitle_reasons`, so series discs with mixed rows surface it
  once, not per row.

No tooltip on the table shell itself (the table has no per-row hover
target that Qt resolves usefully for cell widgets; the combo is the
target).

### 1.5 Data flow: plan keys and run_pipeline signature

**Plan keys (MainWindow._start_run → RunWorker.plan):**

```python
plan["stream_overrides"] = {
    tid: {"audio_sid": int | None, "subtitle_sid": int | None},
    ...
}
```

Wire: `_start_run` copies `self._stream_overrides` verbatim (it already
contains only user-changed tids; both keys always present in a tid's
dict, `None` allowed only for subtitle). `RunWorker.run` forwards it:

```python
result = run_pipeline(
    ...
    title_overrides=self.plan.get("title_overrides"),
    stream_overrides=self.plan.get("stream_overrides"),   # NEW
    ...
)
```

**run_pipeline signature (pipeline.py):**

```python
def run_pipeline(
    index: int,
    outdir: str,
    *,
    ...
    title_overrides: dict[int, str] | None = None,
    stream_overrides: dict[int, dict[str, int | None]] | None = None,  # NEW
    ...
) -> PipelineResult:
```

### 1.6 Merge with recommendations, and the subtitle-None contract

The merge happens **once, at selection time**, immediately after
`recommend_title()` runs in each branch (series and movie); the result
is the authoritative `selected = {tid: Selection}` map that the rest of
the pipeline already consumes. New helper in pipeline.py, ~20 lines:

```python
def _apply_stream_overrides(
    sel: Selection,
    title,
    override: dict[str, int | None] | None,
) -> tuple[Selection, str | None]:
    """override = {"audio_sid": ..., "subtitle_sid": ...} for this tid.

    Returns (selection, note) where note is a warning string when the
    user overrode anything (echoed into result.warnings so the History
    page can see the choice was manual).

    Rules:
    - override is None or missing keys -> selection unchanged.
    - audio_sid in override must exist among title's audio streams,
      else ignore the audio override and keep the recommendation
      (never encode a silent file on a typo'd/stale sid) + note.
    - subtitle_sid may be None ("user wants no subtitles"): the
      selection's subtitle_sid is set to None and a marker attribute
      records the explicit choice so the rip-time fallback can
      distinguish "no selection" from "explicitly none".
    - subtitle_sid set to a real sid must exist among title's subtitle
      streams, else ignore + note.
    """
```

Marker for the explicit None: `Selection` gains one field in
recommend.py, defaulting False:

```python
subtitle_user_declined: bool = False   # v0.2.15: user picked "(no subtitles)"
```

(One-line addition, no behavior change anywhere else; the dataclass is
internal to recommend/pipeline.)

**Where each v0.2.13-fallback rule lives** - the interplay table,
made exact:

| user action | selection.subtitle_sid | subtitle_user_declined | rip-time behavior |
|---|---|---|---|
| nothing (recommendation stands) | sid or None | False | v0.2.13 fallback ACTIVE: if sid missing from the rip, first subtitle stream in the rip is used and a warning is recorded. |
| picks a specific stream | that sid | False | Fallback DISABLED *for that title*: if the sid is missing from the rip, ship no subtitles + the existing G3 warning only. |
| picks `(no subtitles)` | None | True | No subtitle ordinal resolved, no fallback, no OCR, no srt_path. Identical end-state to want_subtitles=False, scoped to this title. |

Implementation points, exact:

- The fallback block in pipeline.py (`if sub is None and want_subtitles:`)
  gains one condition: `and not job.selection.subtitle_user_declined
  and not _was_overridden(job)`. `_was_overridden` is just a lookup -
  `job.tid in (stream_overrides or {}) and
  stream_overrides[job.tid].get("subtitle_sid") is not None`. An
  explicit *choice* and an explicit *decline* both disable the
  fallback; only the untouched recommendation keeps it. The note from
  `_apply_stream_overrides` is appended to `result.warnings` so the
  choice is visible after the run.
- `want_subtitles` (the global checkbox) stays the outer gate:
  unchecked ⇒ no subtitle work for any title regardless of combos
  (combos are still editable but inert; the muted line under the table
  says so when the box is unchecked - one label, set from
  `check_subs.toggled`). Checked ⇒ per-title logic above applies.
- Subtitle OCR (existing `run_subtitle_ocr` call) runs only when
  `sub is not None`, so explicit-None titles automatically skip it.

### 1.7 Dry-run behavior

Dry run must show the override in the returned plan, because the CLI
prints it and tests assert on it:

- `_apply_stream_overrides` runs identically in dry and real runs
  (selection construction is the one shared code path).
- In the dry-run branch, an override note lands in
  `result.warnings`, e.g. `Title 0: user override - audio sid 2,
  subtitles: none`. An explicit None produces `job.srt_path is None`
  and skips the "SRT path reserved" warning for that job, same as
  want_subtitles=False does today.

## Gap 2 - Safe rip reuse (resolution check)

### 2.1 Problem

The v0.2.12 "Verifying existing rip" block (pipeline.py) reuses a
leftover `.mkv` when `probe_duration_seconds` agrees with the scanned
title within `max(60 s, 5 %)`. A Blu-ray and a DVD pressing of the same
movie match that test with identical runtimes; a run against one disc
will happily reuse the other's rip, and encode.py's media_type-dependent
settings (`is_dvd`, SD-resolution handling) then silently process the
wrong master.

### 2.2 Rule: compare width, prefer the scan's own resolution

**Chosen rule (robust to missing scan data): three-tier width check.**

Verify a candidate reuse by probing the existing file's video width and
comparing against what the current disc says this title should be:

1. **Best source.** The scanned title's video stream
   (`title.streams_of("video")[0].resolution`, SINFO attr 19, e.g.
   `"3840x2160"` - present in both test fixtures for real discs).
   Parse `"WxH"`; on parse failure act as if absent (tier 2/3).
   **Exact width match required.** 3840-UHD rips differ from 1080
   Blu-ray issues of the same film; same-runtime editions exist
   (director's-cut discs), so "same disc family, different encode" is
   a real cross-match and must re-rip.
2. **Fallback when the scan has no resolution string** (degraded scan,
   unusual MakeMKV build): classify by `disc.media_type`
   (`"dvd"` | `"bluray"`, from CINFO:1 DISC_TYPE_CODES):

   | disc.media_type | acceptable existing-rip width |
   |---|---|
   | `dvd` | 320..854 (NTSC 720, PAL 720, anamorphic to 854; a 1280+ file is a Blu-ray rip -> reject) |
   | `bluray` | >= 1280 (an SD-width file is a DVD rip -> reject) |
   | other/empty | skip the width check entirely; duration check alone decides (no stronger claim available) |

3. **Neither source available** (no scan resolution and media_type
   unknown): keep v0.2.12 behavior (duration-only). Log nothing extra -
   this is the same confidence the release has today.

Why width and not both dimensions: a single scalar is unambiguous for
the DVD/BD split (720 vs 1920) and avoids a second parse of aspect or
cropping variants (1080 vs 1088, 2160 letterboxed). Height adds no
discriminating power here - everything width 1280+ is a BD-class rip.

Why exact width in tier 1, not `>=`: exact-match is *stricter* than a
threshold, is still robust because both strings come from the same
family of sources (MakeMKV's scan attr vs ffprobe's decode of an
MakeMKV-produced file), and a strict check only ever costs a re-rip -
failing closed is correct for a destructive-reuse decision. A single
exact-width mismatch never misroutes a file the duration check would
have accepted, because a true leftover from *this* disc was ripped
from the same scan resolution.

### 2.3 ffprobe change (ffprobe.py)

**Extend `ProbedStream` with `width`** (one int field, parsed in
`parse_probe` from the stream's `"width"`, default 0), plus one helper:

```python
def first_video_width(streams: list[ProbedStream]) -> int | None:
    """Width of the first video stream, or None when absent/unparsed."""
```

No new probe invocation: the verify block currently calls only
`probe_duration_seconds` (cheap csv format probe). Reuse verification
adds **one** `probe_streams(path)` call on the existing file, made
*only after* the duration probe passes, so the extra ffprobe run costs
~tens of ms and runs at most once per job. Both helpers stay pure and
headless-testable via `parse_probe` (same pattern as
`is_interlaced`/`nth_of_type`).

### 2.4 pipeline.py verify block - exact replacement logic

Inside the existing `if os.path.isfile(job.input_path):` block, after
the duration probe:

```python
_DURATION_TOLERANCE = lambda d: max(60.0, 0.05 * d)   # unchanged
_DVD_WIDTH_MAX = 854    # anamorphic PAL/NTSC ceilings
_BLURAY_WIDTH_MIN = 1280

reusable = duration_ok
if reusable:
    scanned_width = _scanned_video_width(title)   # int | None
    try:
        existing_width = first_video_width(probe_streams(job.input_path))
    except Exception:
        existing_width = None          # treat probe failure as mismatch
    if scanned_width is not None:
        reusable = (existing_width == scanned_width)
    elif disc.media_type == "dvd":
        reusable = (existing_width is not None
                    and existing_width <= _DVD_WIDTH_MAX)
    elif disc.media_type == "bluray":
        reusable = (existing_width is not None
                    and existing_width >= _BLURAY_WIDTH_MIN)
    if not reusable:
        stage(
            f"Existing rip of {job.output_name} is a different master "
            f"(width {existing_width or '?'} vs expected "
            f"{scanned_width or disc.media_type or '?'}) - re-ripping"
        )
```

- `_scanned_video_width(title)`: parses
  `title.streams_of("video")[0].resolution` via one regex
  `(\d{3,5})[x×](\d{3,5})`; returns the width int or None on any
  deviation (missing stream, no match, multi-stream title - use the
  first video stream, matching how `_audio_ordinal` resolves ordinals).
- Error handling: any ffprobe failure on the existing file already
  means "re-rip" (same posture as the duration probe's bare
  `except Exception: probed = None`); width None when media_type asks
  for a comparison counts as a **reject** (fail closed: a rippable
  file whose width we cannot read is not safe to reuse), except in the
  tier-3 "unknown media_type" branch where nothing is known and the
  duration check alone decides - deliberately today's behavior, so the
  safety net never *reduces* what v0.2.12 would accept for a
  genuinely unknown disc.
- A rejected file is deleted through the same `os.remove` path that a
  duration-mismatch file takes today; the anti-hang guarantee (no
  interactive overwrite prompt ever reaches a user) is unchanged.
- The stage-line text above doubles as the History-visible reason,
  matching how "Reusing existing rip" is surfaced.
