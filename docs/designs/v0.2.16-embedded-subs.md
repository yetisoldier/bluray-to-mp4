# v0.2.16 Design Addendum: embedded MP4 subtitles (+ total-remaining header pill)

Status: design only (no code). Author: architect subagent, 2026-10-02.
Companion doc: `docs/designs/v0.2.16-vobsub-ocr.md` (read first - this
addendum assumes the `codec_name` branch it defines).

NEW REQUIREMENT (Eric, 2026-10-02 15:07): subtitles must live INSIDE the
MP4, not only as a sidecar. Today the OCR result is written as
`<video>.srt` next to the MP4 and nothing is embedded.

Constraints: Python 3.14, PySide6, pytest; no new dependencies. Sized to
ship in the same Forge session as the VobSub branch (~15-30 extra min).

---

## 1. The mux step - one ffmpeg remux after OCR

After `run_subtitle_ocr` returns the normalized sidecar SRT (works for
both PGS `.sup` and VobSub `.mkv` branches - the mux is downstream of
and blind to the intermediate format), remux it into the finished MP4
as a soft subtitle track:

```
ffmpeg -y -hide_banner -nostdin -loglevel error \
    -i movie.mp4 -i movie.srt \
    -map 0 -map 1 -c copy -c:s mov_text \
    -metadata:s:s:0 language=eng \
    movie.muxing.mp4
```

`-map 0` carries **every** stream of the encoded MP4 (video, all audio
channels/dispositions the encode plan produced); `-map 1` adds the SRT;
`-c copy` stream-copies everything except the subtitle, which is
converted to `mov_text` - the only subtitle codec the MP4 container
spec supports and the only one VLC, Plex, Jellyfin, Apple TV, and
Windows Media Player all read from `.mp4`. No alternative codec is
needed; there is no second candidate (tx3g is the same thing by another
name; `webvtt`-in-mp4 has worse player coverage than the sidecar we
also keep).

### Placement: inside subtitles.py as a post-OCR mux helper (chosen)

New public helper in `bluray_to_mp4/subtitles.py`, called from
pipeline.py immediately after the existing `run_subtitle_ocr` call.
Rationale:

- **Same failure class.** The mux is part of "get subtitles onto the
  movie", and its failure handling is the existing `SubtitleOcrError` ->
  warning-and-ship contract. Housing it in subtitles.py lets it raise
  the same exception type; pipeline.py gains zero new control flow.
- **Same stubbing seam.** `extract_subtitles`'s ffmpeg call is already
  monkeypatched in tests as `bluray_to_mp4.subtitles.extract_subtitles`
  and takes `binary=`. The mux helper mirrors that shape exactly, so
  tests stub it the same way with no pipeline changes.
- **pipeline.py stays thin.** Pipeline's job is sequencing (rip ->
  probe -> encode -> OCR -> done); the details of subtitle containers
  (`.sup` vs `.mkv` extraction, now `mov_text` muxing) all live in one
  module. (Rejected: mux inline in pipeline.py - it would be the third
  ffmpeg invocation detail in a file that currently knows only one, and
  it would need its own error class or a subtitles import anyway.)

### Signatures

```python
# subtitles.py
def mux_srt_into_mp4(
    video_path: str,          # the finished MP4 (exists; replaced on success)
    srt_path: str,            # normalized sidecar from run_subtitle_ocr
    *,
    language: str = "und",    # ISO-639-2 tag for the embedded track
    binary: str = "ffmpeg",
    runner: Runner | None = None,
) -> str:                     # returns video_path (same path, new content)
    """Embed srt_path as a soft mov_text subtitle track in video_path.

    Muxes to a temp sibling then os.replace()s it over video_path, so a
    failed/interrupted mux can never destroy the encode (Section 2).
    """

def mux_language(lang: str) -> str:
    """ffprobe subtitle language -> MP4 track tag.

    'eng'/'en' -> 'eng'; anything else (incl. '', the v0.2.14
    unconfirmed case) -> 'und'. The OCR pipeline only ever produces
    English text (Tesseract /ocrlanguage:en), so non-English source
    tags would be lies; und = honest 'undetermined'.
    """
```

`run_subtitle_ocr`'s signature and `OcrResult` are **unchanged** - the
sidecar is still produced and returned exactly as before.

pipeline.py call site (inside the existing `if sub is not None:` OCR
block, in the same `try/except SubtitleOcrError`):

```python
ocr = run_subtitle_ocr(
    job.input_path, sub.index, video_out, workdir=rip_dir,
    codec_name=sub.codec_name,                    # (vobsub-ocr branch)
)
job.srt_path = ocr.srt_path
mux_srt_into_mp4(video_out, ocr.srt_path,
                 language=mux_language(sub.lang))  # NEW
result.warnings.extend(f"{job.output_name}: {n}" for n in ocr.notes)
```

Two added lines, zero new branches - a mux failure raises
`SubtitleOcrError` and lands in the same warning as an OCR failure.

### Sidecar disposition: KEEP

The `.srt` stays next to the MP4. It costs nothing, stays editable
(spot-fix OCR typos without remuxing), and players auto-load either.
Eric's stated preference is embedded - that is what ships enabled by
default in the file; the sidecar is a bonus, not a second subtitle
source the player must choose between (Plex/VLC prefer the embedded
track; the sidecar is only a fallback file on disk).

## 2. Failure handling - temp-then-replace, never lose the MP4

Exact sequence inside `mux_srt_into_mp4`:

1. `tmp = video_path + ".muxing.mp4"` (same directory - same
   filesystem, so step 4's `os.replace` is atomic; `tmp_path` in tests
   is flat so no collision with anything).
2. `os.remove(tmp)` if it exists (stale temp from a killed run).
3. Run the ffmpeg command with `tmp` as the output. On FileNotFoundError
   -> `SubtitleOcrError("ffmpeg not found for subtitle muxing: ...")
   (mirrors `extract_subtitles`' message shape). On returncode != 0 or
   missing/empty `tmp` -> delete `tmp` if present, raise
   `SubtitleOcrError(f"subtitle muxing failed: {stderr[:300]}")`.
4. `os.replace(tmp, video_path)` - atomic on every supported platform
   (NTFS included, over an existing destination).
5. On `OSError` from the replace: delete `tmp` if possible, raise
   `SubtitleOcrError(f"subtitle muxing could not replace the MP4: {exc}")`.

Every raise leaves `video_path` **bit-identical** to its pre-mux state
and the `.srt` sidecar on disk - pipelines's existing catch produces:

```
{output_name}: subtitle OCR failed (subtitle muxing failed: ...);
MP4 was produced without subtitles.
```

That text is slightly off for a mux failure (the MP4 *has* no embedded
subs but the sidecar exists). Refine the pipeline warning by stage so
History reads correctly - pipeline.py's except gains one conditional:

```python
except SubtitleOcrError as exc:
    if job.srt_path:
        result.warnings.append(
            f"{job.output_name}: subtitle embed failed ({exc}); "
            "MP4 ships without embedded subtitles; sidecar SRT kept."
        )
    else:
        result.warnings.append(
            f"{job.output_name}: subtitle OCR failed ({exc}); "
            "MP4 was produced without subtitles."
        )
```

(`job.srt_path` is set before the mux runs, so it is the exact
discriminator of which stage failed. A cancel between encode and mux
still raises `EncodeCancelled` from the pre-OCR check - no change.)

## 3. Language metadata - `eng` when confirmed, `und` otherwise

The embedded track's `-metadata:s:s:0 language=` value comes from the
**ripped MKV's** probed subtitle stream (`ProbedStream.lang`, populated
from ffprobe stream tags at the existing `probe_streams(job.input_path)`
call - the probe pipeline.py already does before encode). It is NOT
derived from the disc-scan `StreamInfo`: the v0.2.14 selection can fall
back to a different stream than the scan picked (the "selected subtitle
stream missing" fallback), and the rip's own tags are what ffmpeg
actually saw.

Mapping (`mux_language`):

- `lang in ("eng", "en")` -> `"eng"` (normalized to the ISO-639-2 form
  MP4/players expect).
- Everything else - including `""` (Mamma Mia's untagged PGS: the
  v0.2.14 "English not confirmed by the disc scan" caveat) and any
  non-English tag - -> `"und"`.

Why `und` for a track we believe is English: OCR hard-codes
`/ocrlanguage:en`, so the *text* is English, but the *track tag* is
metadata about the source stream. Stamping `eng` on an unconfirmed
stream would make the honest-state case indistinguishable from the
confirmed case in players' subtitle menus. `und` is the container's
defined "undetermined" value; VLC and Plex render it fine and the
Review page already tells Eric to verify language in that case. If the
disc scan confirmed English, the tag says so.

## 4. Streams preservation - verified by construction

`-map 0` maps every stream of the encoded MP4 in input order (video +
every audio track `build_encode_args` included); `-map 1` adds exactly
one new subtitle stream, appended last. `-c copy` is a bit-stream copy
for video and audio - no re-encode, no quality change, no channel or
disposition loss. The output duration equals the input duration; the
mov_text timebase conversion is timestamp-preserving for SRT input.
Exactly one subtitle track is added and the encode plan never puts
subtitle streams in the MP4 today, so the result has `subtitle_streams
== 1` always. If a future encode plan ever embeds one, `-map 0 -map 1`
would carry both plus the new track; the test at Section 5 pins the
current one-track expectation via command-shape assertion
(`-c:s mov_text` present, `-map 1` present, `-map 0` first).

## 6. Related small item: total-remaining moves to the header pill

Eric reports (14:45) he doesn't see the "Total remaining ~H:MM (all
steps)" string during rip. Cause: `_forecast_total()` only sets
`self.time_remaining`, a QLabel inside the Encode page's **Current**
card (`ui/main_window.py::_build_encode_page`) - invisible from every
other page, and easy to miss even on Encode because `_run_progress`'s
per-stage `self.time_remaining.setText(f"Remaining ~{m}:{s:02d}")`
overwrites the total with the stage-only ETA on every progress tick.

Minimal move - no forecast-model changes, one new widget:

**Widget** (in `_build_ui`'s `header_row`, next to `monitor_pill`):

```python
self.total_pill = QLabel("")
self.total_pill.setObjectName("statusPill")  # same style as monitor_pill
header_row.addWidget(self.total_pill)        # left of monitor_pill
```

**Wiring** (three single-call edits):

- `_forecast_total()` - after setting `self.time_remaining`, also
  `self.total_pill.setText(f"Total remaining ~{self._fmt_hm(secs)} "
  "(all steps)")` (guard: `if secs is None: self.total_pill.setText("")`
  - no run plan, no pill text).
- `_stop_liveness()` - add `self.total_pill.setText("")` (cleared on
  done/failed/cancel, same lifecycle as `time_remaining`). This is the
  single clear point both `_run_done` and `_run_failed` pass through.
- `_run_progress()` - the `Remaining ~m:ss` overwrite must target only
  `self.time_remaining` (already true); the pill is refreshed once a
  second from `_tick_elapsed` -> `_forecast_total`, so it shows the
  all-steps forecast on **every** page during a run and never flickers
  from per-stage ticks. Optionally drop the stage-ETA overwrite of
  `time_remaining` entirely since `_tick_elapsed` rewrites it with the
  total every second anyway - keep it (1:1 UX on the Encode card is
  deliberate) but scoped to `time_remaining` only.

Because `_tick_elapsed` runs every second for the life of the run, the
pill updates on Source/Review/History exactly as on Encode - that is
the whole fix. No `_refresh-monitor-pill` entanglement: the two pills
are siblings, each written by its own owner (`_toggle_monitor`/
`_refresh_monitor_pill` vs `_tick_elapsed`/`_stop_liveness`), and
`_nav_to` calling `_refresh_monitor_pill` never touches `total_pill`.

**Tests** (tests/test_ui.py pattern - existing MainWindow tests construct
directly with `MainWindow(Settings())` plus the `qapp` fixture, and
`test_start_run_populates_plan` / `test_run_progress_overall_math` show
the fake-plan shape):

| file | test name | intent (one line) |
|---|---|---|
| tests/test_ui.py | `test_total_pill_updates_and_clears` | fake plan/run worker + `w._run_started_at = time.time()`; call `w._forecast_total()` -> `total_pill.text()` starts with "Total remaining ~"; call `w._stop_liveness()` -> pill text is `""` and `time_remaining` is `""`. |
| tests/test_ui.py | `test_total_pill_survives_progress_ticks` | after `_forecast_total()` sets the pill, invoke `w._run_progress("Movie", 0, 0.5, 120.0)` -> `time_remaining` shows the stage ETA but `total_pill` still starts with "Total remaining ~" (regression pin for the old single-label overwrite). |
